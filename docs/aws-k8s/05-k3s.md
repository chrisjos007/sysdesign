# Phase 5 — Install k3s (Kubernetes)

[← Phase 4](04-vm-baseline.md) · [Guide home](../../AWS_K8S_DEPLOYMENT.md) · Next: [Phase 6 →](06-cert-manager.md)

**Goal:** a working single-node Kubernetes cluster, `kubectl` and `helm` ready to use, and Traefik answering on port 80.
**Time:** ~20 minutes.

---

## Background: what k3s installs

One binary, run as the systemd service `k3s`, that contains:

| Component | Job | Shows up as |
|---|---|---|
| API server, scheduler, controller manager | The Kubernetes "brain" | Inside the `k3s` process |
| kubelet + containerd | Runs containers on this node | Inside the `k3s` process |
| Flannel | Pod networking (pods get IPs in `10.42.0.0/16`) | `cni0` / `flannel.1` network interfaces |
| kube-router NetworkPolicy controller | Enforces NetworkPolicies | Inside the `k3s` process |
| CoreDNS | In-cluster DNS (`*.svc.cluster.local`) | Pod in `kube-system` |
| Traefik | Ingress controller: routes HTTP(S) from outside to Services | Pod in `kube-system` |
| ServiceLB ("klipper") | Makes `LoadBalancer` Services work by binding ports on the node | `svclb-traefik-*` pod |
| local-path-provisioner | Creates PVCs as folders under `/var/lib/rancher/k3s/storage` | Pod in `kube-system` |
| metrics-server | Powers `kubectl top` | Pod in `kube-system` |

## Step 5.1 — Install k3s

**Where:** 🐧 VM

```bash
curl -sfL https://get.k3s.io | INSTALL_K3S_CHANNEL=stable sh -s - --write-kubeconfig-mode 600
```

- `INSTALL_K3S_CHANNEL=stable` installs the current stable release (v1.36.x at the time of writing).
- `--write-kubeconfig-mode 600` keeps the admin credentials file readable by root only.

**Expected:** output ending with lines like
```
[INFO]  systemd: Enabling k3s unit
[INFO]  systemd: Starting k3s
```

Check the service:
```bash
sudo systemctl status k3s --no-pager | head -5
```

**Expected:** `Active: active (running)`.

**If it fails:** `sudo journalctl -u k3s --no-pager | tail -50` shows why.

- [ ] k3s service is running

## Step 5.2 — Give your user a kubeconfig

**Where:** 🐧 VM

k3s writes the admin credentials to `/etc/rancher/k3s/k3s.yaml`, readable only by root. Copy it for your user:

```bash
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown "$USER": ~/.kube/config
chmod 600 ~/.kube/config
echo 'export KUBECONFIG=$HOME/.kube/config' >> ~/.bashrc
echo 'source <(kubectl completion bash)' >> ~/.bashrc
echo 'alias k=kubectl' >> ~/.bashrc
echo 'complete -o default -F __start_kubectl k' >> ~/.bashrc
source ~/.bashrc
```

This also gives you tab-completion and the short alias `k` for `kubectl`. The guide always writes `kubectl` in full.

**Treat `~/.kube/config` like a root password.** Anyone with it controls the whole cluster.

- [ ] `kubectl` works without `sudo`

## Step 5.3 — Check the node

**Where:** 🐧 VM

```bash
kubectl get nodes -o wide
```

**Expected** (roughly):
```
NAME            STATUS   ROLES           AGE   VERSION        INTERNAL-IP   ...  OS-IMAGE             KERNEL-VERSION   CONTAINER-RUNTIME
ip-172-31-x-x   Ready    control-plane   2m    v1.36.4+k3s1   172.31.x.x    ...  Ubuntu 24.04.x LTS   6.x-aws          containerd://...
```

`STATUS` must be **Ready**.

- [ ] Node is Ready

## Step 5.4 — Check the system pods

**Where:** 🐧 VM

```bash
kubectl get pods -A
```

**Expected:** everything in `kube-system` is `Running`, apart from helm-install pods that show `Completed`:
```
NAMESPACE     NAME                                      READY   STATUS      
kube-system   coredns-...                               1/1     Running
kube-system   local-path-provisioner-...                1/1     Running
kube-system   metrics-server-...                        1/1     Running
kube-system   helm-install-traefik-crd-...              0/1     Completed
kube-system   helm-install-traefik-...                  0/1     Completed
kube-system   svclb-traefik-...                         2/2     Running
kube-system   traefik-...                               1/1     Running
```

It can take 1–2 minutes after install for everything to settle. Re-run the command until it does.

**If CoreDNS is in `CrashLoopBackOff`, or pods keep restarting:** a host firewall is interfering. Check `sudo ufw status` (must be inactive, Phase 3.1), then run `sudo systemctl restart k3s`.

- [ ] All system pods Running / Completed

## Step 5.6 — See how Traefik is exposed

**Where:** 🐧 VM

```bash
kubectl -n kube-system get svc traefik
```

**Expected:** `TYPE LoadBalancer`, `EXTERNAL-IP` = the instance's private IP (172.31.x.x), `PORT(S) 80:…/TCP,443:…/TCP`.

**What this means:** the ServiceLB pod binds ports 80/443 on the node and forwards them to Traefik. The security group + the public IP → node:80/443 → Traefik. You don't need a paid AWS load balancer (an ALB/NLB would cost ~$16+/month).

- [ ] Traefik service present

---

## Step 5.7 — Prove the whole path from the internet

**Where:** 🪟 Windows

```powershell
curl.exe -i http://sysdesignquest.duckdns.org
```

**Expected:**
```
HTTP/1.1 404 Not Found
...
404 page not found
```

A **404 from Traefik is success**: DNS → security group → ServiceLB → Traefik all work, and there are simply no routes yet.

- [ ] 404 from Traefik

**Where:** 🐧 VM

```bash

```

**Expected:** `version.BuildInfo{Version:"v…"}`. Both Helm 3 and Helm 4 work with this guide.

- [ ] Helm installed

## Step 5.9 — Learn five commands you'll use constantly

Try each now against the running cluster:

| Command | What it shows |
|---|---|
| `kubectl get pods -n kube-system` | Pods in one namespace (`-A` = all namespaces) |
| `kubectl describe pod -n kube-system <name>` | Full detail plus **Events** at the bottom. This is the first place to look when anything is stuck |
| `kubectl logs -n kube-system deploy/traefik` | A container's output (`-f` follows it live) |
| `kubectl get events -A --sort-by=.lastTimestamp \| tail -20` | Recent cluster-wide events |
| `kubectl explain deployment.spec.strategy` | Built-in docs for any manifest field |

- [ ] Tried them
