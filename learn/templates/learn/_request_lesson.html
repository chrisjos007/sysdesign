One timeout. Two possible histories.

You submit an order, then see “Request timed out.” Before opening the timelines, sketch a lost request and a lost response. Mark the last event the client and server can each observe.

Compare the two timelines

The request never arrives

  1. Client sends an order request.
  2. The request is lost before reaching the server.
  3. Server receives nothing and saves no order.
  4. Client times out without a response.

The response never arrives

  1. Server receives the order request.
  2. Server commits the order and sends a response.
  3. The response is lost before reaching the client.
  4. Client times out without a response.

The client sees the same outcome. The server can distinguish no request from a committed order; the client cannot infer that distinction from its timeout. Consult server-side state or a stable operation identifier and use an application contract for safe retries.

Which setup steps can the next request reuse?

It may reuse a valid cached DNS answer and a valid established TCP/TLS connection. DNS caching alone does not reuse a connection. A broken connection needs fresh setup.
